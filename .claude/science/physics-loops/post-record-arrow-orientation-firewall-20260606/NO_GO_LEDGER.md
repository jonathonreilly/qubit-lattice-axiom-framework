# No-Go Ledger

## Count state cannot orient the physical arrow

For every finite word `w`, `count(w) = count(reverse(w))`. Count data cannot
distinguish forward from reversed orientation.

## Count-law certificates cannot orient the physical arrow

For any finite law `P` on words, the reversed law `P^R` has the same count
pushforward. Therefore p-values or concentration certificates for count-only
events cannot decide arrow orientation.

## Count state cannot select the production kernel

An asymmetric word and its reverse have identical counts but different oriented
transition counts and different empirical kernels. Counts do not select which
kernel is the physical forward kernel.

## Stable setting is not selected dial

This no-go also preserves the dial firewall: stable settings and count
stability are not selected dial values.
