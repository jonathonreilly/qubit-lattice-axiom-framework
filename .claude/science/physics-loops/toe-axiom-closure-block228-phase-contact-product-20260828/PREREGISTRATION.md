## Mechanical product compiler

Before graph execution, enumerate the finite Cartesian product

```text
controller source class
x exact incident-F subset on every displayed labelled dart
x boundary class {root,interior,seam,Y/parallel}.
```

For each complete local cylinder, compile by this frozen algorithm:

1. Compute the controller read set and write set from its literal source and
   target, including darts rather than onsite letters alone.
2. If every incident participant touches only sites and darts left unchanged,
   tensor it through exactly.  This is the sole read-only lift.
3. If a controller writes a contacted site or dart, form the simultaneous
   controller/contact critical cell.  Do not suppress either event.
4. Reduce both primitive successors using only already compiled cells of
   strictly smaller structural rank.  Emit one atomic product row only when
   they have one identical bounded full-state join with the same terminal
   obligation and every participant accounted for.
5. If the two sides lack a unique join, require support above the frozen
   bound, require a new onsite state, or depend on priority, emit no row and
   stop with that first complete cylinder and both histories.
6. Exact cylinders with no physical action receive identity only at the CP
   compilation stage.  Identity cannot mask an unserviced contact.

The primitive contact kernels frozen before execution are the inherited
`C0/CQ/CF` cells, the direct-root contact cell, and the simultaneous root-turn,
good-return, discovery, and seam-boundary cells obtained by the algorithm
above.  Their concrete rows must be printed as one generated table before any
word is explored.  Adjacent and separated two-contact cells are generated by
the same subset product; they are not special cases.

The compiler order is canonical serialization of boundary class, controller
class, exact labelled mask, and source state.  This order selects which defect
is reported first, never which physical row fires.
