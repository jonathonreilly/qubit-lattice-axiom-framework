# Validation checklist and execution boundary

Completed before this source package was prepared: the complete ordinary proof
and final focused review were read and accepted by root; the exact source and
complete author/reviewer/root records were preserved. Review independence is
limited as stated in REVIEW_HISTORY.md. Main-parent mathematical changes were
checked by complete diff reads; there were none.

Source preparation performs deterministic copying, hashes, archive identities
and a reconstruction inventory only. It executes neither the new primary tool
nor the installation driver, graph builders, cache APIs, source validators,
mathematical controls, Git mutations, audit or PR operations.

Root must read the final frozen sources, full driver/diff, canonical tool and
packet before recording execution acceptance outside the frozen preparation.
Root's bounded driver then requires the exact clean base and branch, verifies
procedure identities before use, builds the fresh base graph, installs only the
reviewed payload, parses primary syntax, checks metadata and local links, and
runs report-only vocabulary checks. Indented mathematical text is excluded from
Markdown-link extraction.

The canonical identity tool is executed only through runner_cache with its true
60-second timeout. Complete raw INNER and OUTER returns and available merged
stdout/stderr are preserved before interpretation. The API does not expose a
separate original child stderr stream; this limitation must remain explicit.
No scientific predicates, scientific mutations, mathematical proof validation or
N5 PASS can be inferred from that execution.

The driver builds the final citation graph and manifest, checks exactly one new
node/three new edges with all old complete nodes and edges preserved, and runs
focused existing-ledger compatibility. It requires the new primary identity
cache to be fresh. The three parent cache statuses are diagnostics only; no
parent runner is rerun or refreshed, and no parent audit status is changed.

Actual execution receipts live outside the frozen preparation. On success the
driver adds deduplicated runtime evidence to the installed packet and writes a
PR body populated with actual validation. On failure it retains all completed
streams and partial installation, stops and requires root to inspect the failure
before any recovery. No automatic retry or silent source correction is allowed.

Applicable source, metadata, citation and focused-evidence checks precede the
regular review PR. Combined current-main landing validation, strict audit lint
and formal retained audit remain separate later obligations. No claimed proof
coverage is inferred from hashes, file counts or cache freshness.
