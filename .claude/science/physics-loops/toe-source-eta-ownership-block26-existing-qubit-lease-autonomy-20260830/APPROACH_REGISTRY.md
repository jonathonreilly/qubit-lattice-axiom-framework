# Block26 approach registry

The normalized approach families differ in primary object or load-bearing
mechanism; different code representations do not count as new routes.

| ID | normalized family | status before execution |
|---|---|---|
| A | supplied hard-core complete-carrier tensorization | preregistered direct proof |
| B | deterministic single-valued covariant selector | preregistered exact pair and cycle attack |
| C | stochastic joint recorded owner instrument | preregistered constructive counterroute |
| D | exact common-target clique instrument on existing pointer qubits | preregistered constructive control |
| E | persistent or growing Record-history priority | open, not executed in Gate 1 |
| F | finite spatial auxiliary status/port code | open prior-art bridge |
| G | direct coherent/unsharp partial-overlap controller | open |
| H | factor-of-IID/static stochastic hard-core field | prior spatial construction; fresh-field and dynamics conditions open |
| I | global history/process selection | open architecture |

Stop work on any family once its load-bearing terminal is exact. Do not grow
A or D by cataloguing more safe fixtures after the arbitrary finite or
all-clique theorem is established.
