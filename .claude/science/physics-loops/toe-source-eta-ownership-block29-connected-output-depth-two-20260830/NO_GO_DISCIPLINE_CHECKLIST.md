# Block29 preexecution negative-claim gate

No negative claim is targeted.  The expected result is a positive finite
composition corollary for both supplied `q` tables.

- A one-sided computational failure is presumed to be a control or
  implementation defect until an independent exact `q`-dependent obstruction
  is proved.
- A common failure closes only the named connected composition architecture;
  it does not distinguish the two tables.
- Failure of a visible classical cause would leave direct, hidden-classical,
  quantum, alternate-carrier, compiler, and autonomous-process routes live.
- Timeout, memory pressure, cache failure, or incomplete classification is not
  physics evidence.
- Any bounded negative discovered after execution must pass a fresh N1--N8
  No-Go Discipline packet before it can be packaged; otherwise it is demoted
  to an open implementation wall.

The broad gate is therefore `FAIL_not_sought` at preregistration.
