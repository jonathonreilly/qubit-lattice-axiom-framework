# October TOE-ruleset campaign: recovery pack

This folder recovers science from the local workspace of the October 2026 "TOE ruleset" campaign that never reached `main`. It was built on 2026-11-19 from three untracked folders: `.claude/science/toe-ruleset-20261021/`, `.claude/science/physics-loops/scale-ladder-gravity-20261018/` and `.claude/science/derivations/three-generations-2026-10-23.md`.

**Standing.** Nothing here is checked, audited or `retained`. Each note is an author statement, `argued` at most (`docs/ai_methodology/RULES.md` section 1). Landing this pack grants no standing, adds no ledger rows and changes no claim on `main`. Labels CL-1 to CL-5 in these files are the campaign's own working laws (see the snapshot below), not the entries of the same number in `docs/CANDIDATE_LAWS.md`. Many results are conditional on those supplied laws.

## Why it lives here

- `AGENTS.md` names dated campaign packs as history, read for recovery and never run as procedure. This is one.
- `RULES.md` section 5: unpushed work does not exist for anyone else, and on a stop dirty or unpushed work is preserved. The workspace was about to be cleaned up.
- `procedures/research.md` keeps working state under `.claude/science/`. The landing depth script (`skills/review-loop/scripts/review_depth.py`) lists `.claude/science/` as working material, so this unit adds working material only.
- It is not under `docs/`: the `SETTINGS.md` row "Proof verification" lets a note land there only with a primary runner that has a perturbation control, and these notes were never brought to that form. It is not under `research/`: these results read the framework axioms and the campaign's candidate laws, and `research/` is for mathematics in which no framework axiom enters.

## Layout

- `agents/<item>/`: one folder per captured item. `note_draft.txt` (or `NOTE.md`) is the note, `runner.py` the runner, `out.txt` the saved output from October, `rerun_2026-11-19.txt` this recovery's rerun, `stems.txt` the file names the campaign planned for `docs/` and `scripts/`, `criteria_pre_run.txt` the criteria written before a run where one exists.
- `CANDIDATE_LAWS_snapshot_2026-10-21.md`: the campaign's working register (laws CL-1 to CL-5, consequences, untested predictions, where the rules are incomplete), byte-identical to the workspace file of 2026-10-21. It is a dated snapshot. It does not replace `docs/CANDIDATE_LAWS.md` and has no premise weight.
- `derivations/three-generations-2026-10-23.md`: a proposed family mechanism with its decisive check stated in advance. The `misfold-generations` run refutes it.
- `INDEX.tsv`: one row per captured item, the same data as the tables below.

## How the items were chosen

Six reader sessions triaged every item of the workspace (530 rows; one row per item, some items read twice). Their verdicts were merged by item name. An item is captured when a reader marked it CAPTURE and it is not already carried in an open PR. Four reader flags were settled by reading the primary files: `mass-rule` and `dark-matter` (CAPTURE against NEGATIVE-LOG) are captured as runner-only results, `spont-generations` is captured with the runner the lead named, and `misfold-generations` carries the three-generations derivation as its pre-registered hypothesis.

Tiers were computed by script, not taken from the readers, from the file lists of the umbrella PRs and from the "Carried" and "Logged" sections of their map notes at these heads: #10124 `00d6c398a4`, #10126 `8f40f2e2db`, #10127 `8b55179517`, #10128 `4dd2b4349b`, #10129 `01897b3e82`, #10131 `2425ff07f9`. `main` was read at `8b11ae2bb9`.

- **Tier B:** an open umbrella map quotes its scope as a "logged" row, but carries no note, runner or output.

## Rerun of 2026-11-19

Each captured runner was run once, one at a time, from a copy of its folder, with `OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1`, `nice -n 10`, a 120 s alarm (`perl -e 'alarm 120; exec @ARGV'`) and a 2 GB memory stop. One change from the requested command: `python3 -I` cannot import numpy on this machine, because numpy, scipy and sympy are installed only in the user site, which `-I` turns off (checked on `baryogenesis`: `ModuleNotFoundError: No module named 'numpy'`). The runs used `python3 -E -P` instead: environment variables ignored and the script folder kept off `sys.path`, with the user site on. Python 3.13.5, numpy 2.4.4, scipy 1.17.1, sympy 1.14.0. No package was installed.

Outcome: **249 pass**, **9 fail**, **0 timeout**, 1 ran with exit 0 but print no PASS/FAIL total. "Pass" means exit 0 with no failing check. Totals are written PASS/FAIL. A rerun is the same calculation run again: it shows that the code still runs and prints what it printed; it is not a check (`RULES.md` section 3). A runner that passes a constant `True` to its check function is flagged with the count.
