# Lane process, effective 2026-10-29 (owner decision)

This applies to new lanes. Lanes that were already running when this was decided may finish in the older format.

1. **Edit in place.** Apply fixes directly in the file. Git keeps the history, so do not keep struck-out or quoted original text inside files. The review (or lane log) names each fix and the commit that made it.
2. **Pre-register numerical checks only.** Write the criteria file before the script, with statements and thresholds only. Report failed checks as failures. Label any post-hoc probe as post-hoc. Written proofs do not need a pre-stated section.
3. **Independent review is still required.** Every substantive result gets a fresh hostile reviewer, who ends with `VERDICT: LAND` or `VERDICT: HOLD`. Disclose same-family review (Codex reviewing Codex) as such.
4. **Rebuild, don't cite.** If a step needs a literature lemma, rebuild it here as a library entry, with credit to the original authors. A citation is attribution only and never carries weight in the proof. Link open papers (arXiv) rather than committing their PDFs.
5. **One clean proof before anything goes public.** A consolidation lane assembles the reviewed pieces into a single proof document that links to its reviews. The lane files are a research log, not the deliverable.

Unchanged: the numeric resource rules (lock, nice, threads = 1, memory limits), no axiom edits, no audit or ledger files, and credit to Balaban and Dimock in every public text.
