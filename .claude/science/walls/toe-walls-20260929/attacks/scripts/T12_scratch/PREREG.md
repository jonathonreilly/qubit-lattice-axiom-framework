## Question the test decides
Route R1 says: the "3+1" of T12 is a COUNTING wall. Let an event poset on Z^3 be
generated by nearest-neighbour precedence (Lattice + Admissibility locality), with
each site contributing ONE event (site-once records). Then for x <= y with longest
chain (height) h, every z in the interval [x,y] has l1-distance <= h from x, so
   N(x,y) = |[x,y]| <= B3(h) = (2h+1)(2h^2+2h+3)/3     (the l1-ball of Z^3).
Interval size grows at most like h^3 (a 2+1 causal set), never h^4 (3+1).
If a site may host many events (turnover), N can grow like h^4.
"Passing" 3+1 therefore costs: events per site that grow linearly with height.

## Ensembles (all measured with the same code; events topologically indexed)
E1 level/product order on Z^3 (x<y iff y-x >= 0 componentwise): site-once, skew. Analytic.
E2 Eden growth from a point seed (first-passage with iid Exp(1) site weights), edges
   oriented by formation time; site-once, cubic covariant rule, single seed. 61^3 box.
E2b Same growth from a flat seed plane (front is a 2D surface). 61^3 box.
E3 iid uniform formation times (random sequential formation): site-once, covariant.
E4 asynchronous cellular-automaton events (each site updates at Poisson rate 1; an update
   depends on the latest events at itself and its 6 neighbours): turnover, q = 1.
E5 moving records (symmetric exclusion, hop rate 1, densities rho = 0.5 and 0.2); events =
   accepted hops; a hop depends on the latest events at its origin and destination site.

Measurement: for random targets y and sources x with longest-chain height h(x,y) = 2..H,
record N(x,y) (endpoints included). Fit p in N ~ h^p by least squares of log(median N)
on log h over h in [4, Hmax]. Also report N/B3(h).

## Addendum (written after a smoke run, before the final run; disclosed)
A first quick smoke run (small boxes, 2 s) used "median N over x drawn at random among ancestors at
height h". It gave exponents near 1-1.5 for EVERY ensemble, including the exact synchronous 3+1
lattice calibration that I added, because random ancestors at fixed longest-chain height are
dominated by near-null separations (thin diamonds). The volume-height lemma bounds the MAXIMUM
interval at height h, so the estimator was changed BEFORE the final run to: for each (y, h), take
the 25 ancestors x with lp(x,y) = h that are l1-nearest to y (rest-frame choice), report max and
median N. Readings (a)-(e) above are applied to the MAX exponent p_max and to the local slope of
the upper third of the h range (p_max_upper_third), because small-h slopes are biased low
(for the exact product order the true exponent 3 is approached only as 3h/(h+3)).
Added calibration E6: exact synchronous Z^3 x N lattice (7 predecessors), a genuine 3+1 poset.
Reading (c) is judged RELATIVE to E6 and E1: turnover ensembles must lie clearly above E1's
p_max and N/B3(h) must rise with h; E6 must rise, E1 must be flat.

## Addendum 2 (after the first full run; disclosed)
The first full run (interval_exponent_results.json, 12 s) did NOT meet pre-registered reading (c):
E4 p_max 3.13 (upper third 3.61), E5 rho=0.5 p_max 2.62 (2.87), E5 rho=0.2 p_max 3.02 (3.17), and
N/B3(h) FELL with h instead of rising. Reading (d) ("turnover not sufficient at this size") is
therefore in play. The exact synchronous calibration E6 gave p_max 3.59 (upper third 3.87) and
N/B3(h) rose from 0.32 to 1.30 (it leaves the site-once ball at h ~ 30), so the estimator can see the
effect when it exists. Cause suspected: in the random-update posets a chain step is a single event, so
chain height h is inflated relative to elapsed time and the h-range (4..280) is too short to reach
asymptotics. Follow-up scale_check.py (pre-committed reading): run E4, E5 on larger boxes/longer times
with log-binned slopes; the turnover claim is judged by whether the top-decade local slope exceeds 3.3
and keeps rising with the size of the run; if the slope stays at or below 3.3 the claim "turnover
suffices for a 3+1 count" is reported as UNSUPPORTED by these ensembles (only E6 and the argument).
