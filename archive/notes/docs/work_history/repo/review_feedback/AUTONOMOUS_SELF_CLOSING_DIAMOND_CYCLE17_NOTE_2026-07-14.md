## Result Up Front

The strongest autonomous post-seed self-closure route works for one isolated
finite diamond and for mutually disjoint copies.

A single finite realized seed—one typed permanent record—can grow its own
finite closed boundary, generate its own stop and source roles, prepare its own

translation/proper-cubic covariant nearest-neighbor law on one `M2(C)` per
actual site. It uses no supplied stop markers, no prepared proposal carriers,
no blank corridor, no global future oracle, and no external cursor.

The fence is the radius-two cubic shell around an open output site. In the
terminology of this probe, it is the **radius-two cubic fence**. It contains
98 lattice sites and is the smallest axis-aligned integer cube shell that
leaves the output's six nearest neighbors in the interior. A fixed typed
Hamiltonian construction path visits every shell site once, plus one interior
connector. Each path record writes only its nearest-neighbor successor. The
last path record is at a face center; because path stages are permanent and
strictly sequential, its existence proves that all earlier shell records exist.
It then writes one interior root record across one edge.

The one connector is not decorative. The shell graph is bipartite with 50
even-parity versus 48 odd-parity sites, so it cannot itself possess a
Hamiltonian path: any alternating path has color-count difference at most one.
One unused odd interior site changes the count to `50:49`; the runner verifies
an exact 99-site NN Hamiltonian path. Thus the connector is the minimum parity
repair for this sequential construction strategy.

After the shell closes, the root grows two short, disjoint internal record
branches. Each branch law-prepares an arbitrary open carrier as `|+>` and
records that preparation beside it. The proposal then makes one terminal
nearest-neighbor `SWAP` into the appropriate merge input. The target input
need not be blank: SWAP moves the proposal exactly through an arbitrary open
state. The displaced state is erased/prepared into the permanent terminal
record. That terminal record writes `K` one edge away. Both `K` records are
nearest neighbors of the output.

Only after both `K` records exist does the output carrier reset to `|0>`, take
the two commuting proposal-to-output CNOTs, and record even or odd parity.
For `|+>|+>` proposals, the two supplied projective/Born branches have weight
`1/2`; they leave `Phi+` and `Psi+` endpoint states respectively. The law
therefore generates rather than assumes the Cycle 16 proposal preparations,
target blanks, source records, and stop markers.

## Geometry: The Minimum Closed Cube for an Open Merge

Use a relational cell `(t,d,e)` with perpendicular unit directions and
`u=d cross e`. Canonical local coordinates `(x,y,z)` map to

```text
t + x e + y u + z d.
```

The boundary is

```text
max(|x|,|y|,|z|)=2.
```

It contains `5^3-3^3=98` sites. The interior contains the output `(0,0,0)`,
both input sites `(0,0,+/-1)`, the two proposal terminals, close records, and
program branches. A radius-one shell would occupy all 26 noncentral sites of
the `3x3x3` block, including every NN input, so radius two is minimum for this
axis-aligned shell strategy.

The shell is a vertex separator. In a `[-3,3]^3` domain, breadth-first search
finds no path from `(3,0,0)` to the output when all 98 shell sites are recorded.
Deleting the face-center record `(2,0,0)` opens an explicit path. Fence
completeness is therefore load-bearing topology, not a visual metaphor.

## Multiple Seeds and Collisions

### Disjoint seeds

### Nearby or differently oriented seeds

Each stage is a distinct permanent content. Translating a second seed by one
site produces many shared targets at which the two paths demand different
stage contents. Properly rotating a second path at the same center has the same
problem. Whichever content writes first blocks the other. This is an explicit
overlapping-seed collision, not a proof that every self-assembly code must
fail.

1. a hard-core nucleation law that never admits overlapping seeds;
2. a same-content abelian fence whose local merges do not conflict;
3. a braid/reroute protocol that allocates distinct construction paths; or
4. a global-history/QCA constraint that admits only compatible complete cells.

The same-content route has a sharp trade: if every shell record is identical,
collisions can merge, but a distinguished terminal content is no longer proof
that all 98 shell sites were reached in the intended order. An additional
acknowledgment code is required.

Arbitrary overlapping seeds remain nonconfluent for the displayed law. Global-
history and QCA escapes remain live.
