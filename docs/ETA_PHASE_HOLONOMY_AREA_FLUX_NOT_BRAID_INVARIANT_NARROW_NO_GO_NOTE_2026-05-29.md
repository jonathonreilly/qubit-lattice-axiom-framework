## 2. The spin-connection setup

Let `V ~= C^2` be the one-qubit site Hilbert space from
[`MINIMAL_AXIOMS_2026-05-20.md`](MINIMAL_AXIOMS_2026-05-20.md), with on-site
Pauli operators `sigma_1, sigma_2, sigma_3`. The staggered (Kogut-Susskind)
phases in the canonical 3D convention are

```
    eta_1(x) = 1,   eta_2(x) = (-1)^{x1},   eta_3(x) = (-1)^{x1+x2},
```

i.e. `eta_mu(x) = (-1)^{ sum_{nu < mu} x_nu }`. This is the standard KS
generalization of the 1+1d repo convention (`eta_0 = 1`, `eta_1(t) = (-1)^t`)
used in `axiom_first_rp_two_step_transfer_matrix_positivity.py` and
`axiom_first_rp_spin_basis_single_step_psd_failure.py` (there the second-listed
direction's phase is `(-1)^{first coordinate}` — exactly `eta_2 = (-1)^{x1}`
here).

Define the **spin-diagonalizing gauge** (Kawamoto-Smit staggering transform)

```
    T(x) = sigma_1^{x1} sigma_2^{x2} sigma_3^{x3} .
```

The runner verifies, **exactly** (zero symbolic deviation) on a `3^3` and a
`4^3` block, for all `mu in {1,2,3}`:

```
    T(x)^dag sigma_mu T(x + mu_hat) = eta_mu(x) * I_2 .              (ID)
```

`(ID)` says that in the rotated (spin-diagonal) frame the Dirac hop operator
`sigma_mu` reduces to the **scalar** phase `eta_mu(x)`. Thus the `eta`-phases
are literally the parallel-transport (connection) phases of a `Z_2` connection

```
    Omega_mu(x) := eta_mu(x)  in  {+1, -1}
```

living over the **base** lattice `Z^3`. The matter sector hops with this scalar
connection in the spin-diagonal frame. *(This is precisely why the staggered
formulation diagonalizes the spin structure: the `eta`-phases ARE the discrete
spin connection.)*

## 3. The curvature: `-1` per face (uniform `pi`-flux), gauge-invariant

The `Z_2` plaquette curvature in plane `(mu, nu)` based at `x` is the oriented
holonomy of `Omega` around the unit cell:

```
    F_{mu nu}(x) = Omega_mu(x) Omega_nu(x + mu_hat)
                   Omega_mu(x + nu_hat) Omega_nu(x) .
```

The runner verifies on a `4^3` block, in **every** plane `(1,2)`, `(1,3)`,
`(2,3)`:

```
    F_{mu nu}(x) = -1   for every unit face.
```

This is a **uniform background `pi`-flux**. It is **gauge-invariant**: under an
arbitrary `Z_2` gauge transformation `Omega_mu(x) -> g(x) Omega_mu(x) g(x+mu)`
with `g(x) in {+1,-1}`, the runner confirms every plaquette curvature is
**unchanged** (max change `0` over the block). So `-1`/face is a genuine
gauge-invariant feature of the connection, not an artifact of the staggering
gauge `T(x)`.

## 4. The holonomy: `(-1)^{enclosed area}`

For a `Z_2` connection, discrete Stokes gives that the holonomy around any
closed base loop is the product of the curvatures of the enclosed faces. With
`F = -1`/face this is

```
    hol(closed loop) = (-1)^{enclosed area}.
```

The runner verifies the **area law** directly: an `a x b` rectangular base loop
has holonomy `(-1)^{a b}` for **all** `a, b in {1..4}` (16 rectangles, every one
closing). Concretely (numbers from the runner):

| loop | enclosed area | holonomy |
|---|---|---|
| `1x1` rectangle | 1 | `-1` |
| `1x2` rectangle | 2 | `+1` |
| `2x3` rectangle | 6 | `+1` |
| `3x3` rectangle | 9 | `-1` |
| `4x4` rectangle | 16 | `+1` |

For a **two-token exchange**, the spinor-frame holonomy is the product of the
two tokens' base-connection holonomies along their trajectories. The three
named exchange loops give (runner numbers):

| exchange loop | enclosed area | holonomy |
|---|---|---|
| **Y-move / zero-area straight swap** (Abrams branch exchange) | 0 | **`+1`** |
| **`1x1`-detour swap** | 1 | **`-1`** |
| **`1x2`-detour swap** | 2 | **`+1`** |

Each is a **faithful, collision-free** swap (the runner checks the tokens never
co-occupy a site and that they exchange endpoints): tokens `A = (0,0,0)` and
`B = (1,0,0)` exchange, one of them taking the detour while the other moves
straight along the `x1`-axis.

## 5. The obstruction: homotopic swaps, different signs

The decisive fact is that the **`1x1`-detour swap and the `1x2`-detour swap are
the SAME element of the graph-braid group `B_2(Z^3)`** — yet they have
**different holonomies** (`-1` vs `+1`). The runner verifies all three legs:

- **(i) Same permutation.** Both swaps send token `A -> B` and token `B -> A`
  (verified endpoints). They realize the identical exchange.
- **(ii) Collision-free.** Under a synchronous clock the two tokens never
  co-occupy a site in either swap (verified). So both are genuine paths in the
  configuration space `UD_2(Z^3)` of two indistinguishable tokens on the site
  graph.
- **(iii) Homotopic in `UD_2(Z^3)`.** Token `B` takes the **same** single
  straight step in both swaps, so the **difference loop** (perform the
  `1x1`-swap, then the `1x2`-swap in reverse) is carried entirely by token `A`
  and is a **closed single-token base loop** that returns both tokens to start
  (verified). That difference loop bounds exactly **one unit cell** (the
  `1x1` square between the two detours), which is **null-homotopic in
  `UD_2(Z^3)`**: a unit square in `Z^3` is fillable by sliding through the third
  lattice direction (with the other token parked away), so it is contractible.
  Hence the two swaps are **homotopic** — the same braid class. The runner
  confirms the difference loop's holonomy is `-1`, equal to the product of the
  two swap holonomies, so the two swaps **differ by exactly that area-flux**.

A fermionic exchange sign is, by definition, a representation of the braid group
on `{+1, -1}` — a **homomorphism** `B_2(Z^3) -> Z_2`, which takes **one** value
on each braid class. The `eta`-holonomy takes **two** values (`-1` and `+1`) on
the **single** braid class of the swap. Therefore:

> **The `eta`-holonomy is not a braid invariant; it is the geometric
> area-flux.**

## 6. The structural reason: a base connection is blind to `pi_1(UD_2)`

The underlying reason is structural, not accidental:

- The `eta`-connection `Omega_mu(x)` lives over the **base** lattice `Z^3`. Its
  holonomy is a function of the **enclosed base area** of a loop.
- The exchange `Z_2` that a fermion sign must represent lives in
  **`pi_1(UD_2(Z^3))`** — the graph-braid group of the **configuration space**
  of two tokens, *not* the base.
- These are different spaces. A single braid class contains representatives of
  **arbitrary** enclosed base area (§5: `1x1`, `1x2`, …), and a loop with
  nontrivial base area need **not** be a braid generator at all. The runner
  exhibits the latter directly: a **single-token `1x1` base loop** has
  nontrivial holonomy `-1` (the area flux of one face), yet it is
  **null-homotopic in `UD_2(Z^3)`** (a fillable unit square in `d >= 3`) and so
  is **not** an exchange/braid generator.

A holonomy that is (a) nontrivial on a null-homotopic, non-braid loop and (b)
multivalued on a single braid class is **structurally incapable** of being a
function of the braid class. The base connection is **blind** to the braid
class. This is why the most natural lattice-native realization of the FS
graph-braid path fails: it puts the spin structure on the **base**, but the
exchange sign lives in `pi_1` of the **configuration space**.
