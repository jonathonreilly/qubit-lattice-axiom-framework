## 1. Precision — the `m_W/256` relation is NOT exact

With PDG `m_e, m_μ, m_τ` and the Brannen square-root mean
`a = (√m_e + √m_μ + √m_τ)/3` (the same coordinate the `open_gate` note uses):

```text
a²              = 313.8411 MeV
m_W / 256       = 313.9422 MeV          (m_W = 80369.2 MeV)
offset          = +0.0322%
empirical N     = m_W / a²  = 256.0824
```

The integer `256` is `−0.0322%` from the data-preferred divisor `256.08`.
Crucially, `m_W`'s own experimental uncertainty (`±13.3 MeV`, `0.0165%`)
gives a window on the divisor of

```text
N ∈ [256.040, 256.125]      (m_W = 80369.2 ± 13.3 MeV)
```

which **does not contain `256.000`**: the integer is `≈ 1.95 σ_(m_W)` away.
So the relation `a² = m_W/256` is **not exact** — the data actively prefers
a non-integer divisor near `256.08`. The "256" in the open gate is a rounding
of `256.08`, not a measured perfect power. (This does **not** refute the open
gate; it sharpens what a future derivation would have to reproduce: either
`256` exactly with a `~0.03%` theory/RG correction, or the `256.08` directly.)

The `(★)` factorization of the lepton-scale probe is, given the gate,
**algebraically exact**:

```text
y_scale = g_2 · (1/√2) · (1/256)  ≡  (m_W/256) · √2 / v   (using m_W = g_2 v/2)
```

and differs from the data Yukawa `a²·√2/v` by *exactly* the `0.0322%` gate
offset (runner §A'). The observed `y_τ = m_τ √2 / v = 0.0102` is reproduced
to that same `0.03%`. So the **precision** of the whole construction is
inherited entirely from the `m_W/256` gate: `0.03%`, i.e. `≈ 2 σ` of `m_W`.

## 3. The exponent `4` does NOT survive `d = 3+1` — the artifact test

The decisive test, per the attack's own guard, is whether the exponent `4`
(or the `taste = 16 = 2⁴` reading) is a genuine count or a **d=4 Euclidean
artifact** that dissolves on the framework's established **d = 3+1** surface
(`Z³` spatial substrate plus emergent time;
[`3D_CORRECTION_MASTER_NOTE.md`](3D_CORRECTION_MASTER_NOTE.md)). It does not:

```text
Z³ spatial corner count            = 2³ = 8        (NOT 16)
taste-squared in d=3+1             = (2³)² = 64    != 256   → 16² is a d=4 artifact
dim_C M_2 ^ (d_spatial = 3)        = 4³  = 64      → predicts m_W ≈ 20 GeV (−75%): FAILS
```

Both structural stories for the exponent break in `d = 3+1`:

- **`(dim M_2)^d` tensor reading.** `M_2(C)^{⊗4}` has dimension `256` only if
  there are **four** tensor copies. In `d = 3+1` the natural site count is the
  `2³ = 8` spatial corners, giving `4³ = 64`, which mispredicts `m_W` by
  `75%`. To keep four copies one must count the **emergent time** as a fourth
  tensor factor — an input, not a derived count. The retained `M_2`-tensor
  note states this directly: `d = 4` is an *explicit bounded parameter*.

- **`(2^d_taste)²` taste reading.** `256 = 16² = (2⁴)²` ties to the hierarchy
  exponent `16` (PR #2717,
  `HIERARCHY_VALUE_FRONTIER_PROBE_2026-06-05.md`, branch
  `codex/hierarchy-value-frontier-2026-06-05`, not yet on main; plain backtick).
  But that `16 = 2⁴` is exactly the naive-lattice species count whose
  identification with a physical exponent is a **regulator-dependent no-go**
  (Wilson `1`, twisted-mass `2`, staggered `4`, overlap `1`; only the *naive*
  operator gives `16`). On the `Z³` spatial lattice the corner count is
  `2³ = 8`, so the taste-squared reading would give `8² = 64`, not `256`. The
  `16/256` reading is a `d = 4` artifact, **not** a clean tie to the
  hierarchy.

The **only** way to retain exponent `4` is to supply an undetermined input —
either "count the emergent time as the fourth tensor factor" or the
self-referential "`base^base`: number of copies equals the dimension of one
copy" (`4^4`). Neither is on the retained surface. **The exponent is not
derived; it is the open content.** This is the load-bearing finding and the
reason the verdict is not `256-STRUCTURAL`.

So the trial-factor inflation from "any nice number would have worked" is
**small**: the integer `256` is a low-look-elsewhere hit. What keeps this from
being declared structural is **not** the integer's rarity (it is rare) but

**two** distinct physical readings (`(dim M_2)^4` tensor and `(2^d taste)²`),

The honest accounting: the look-elsewhere penalty is concentrated **not** in
the choice of integer (`256` is uniquely close) but in the choice of
**exponent/decomposition** of that integer — and that choice is exactly the
undecided part.

## 5. Answers to the four attack vectors

- **(1) Is the exponent `4` derivable?** **No** on the retained surface. Base

  and all physical stories (`base^base`, `d_spacetime`, Dirac-`4`-components)

  **exponent**.

- **(2) Connection to the hierarchy exponent `16`?** `256 = 16²` ties to the
  hierarchy `α_LM^16`, but the `16 = 2⁴` is the *naive-lattice* taste count
  under an existing **regulator-dependence no-go**; in `d = 3+1` the spatial
  corner count is `2³ = 8` and the taste-squared reading gives `8² = 64`, not
  `256`. The `16/256` connection is a **d = 4 artifact**, not a clean shared
  structure (§3).

- **(3) Ruthless look-elsewhere.** The penalty for the **integer** `256` is
  **low** — it is the unique perfect power within `±5%`, no simple rational
  competes, a-priori chance `~0.7%` (§4). The penalty lives in the
  **exponent/decomposition** choice, which is the undetermined part. The
  `m_W/256` relation is **approximate**, not exact: residual `+0.0322%`, with
  the data preferring `N = 256.08` (§1).

- **(4) Precision.** The `(★)` factorization is algebraically exact given the
  gate; the whole construction reproduces `y_τ = 0.0102` to `0.0322%`, which

Until such a route lands, the lepton Yukawa suppression is **a structural
