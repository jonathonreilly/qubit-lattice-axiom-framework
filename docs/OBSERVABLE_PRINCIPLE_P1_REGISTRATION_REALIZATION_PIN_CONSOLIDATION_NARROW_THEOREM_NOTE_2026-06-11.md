## 2. The formalization (what a clause is a predicate over)

A finite **realization model** carries, per e-fold `k`: the declared
readout increment; a finite collection of records, each with a sector
datum, an abstract pairwise-orthogonality sector label, a register-site
support, an establishment flag (retained finite-range dynamics with
bounded-region, norm-bounded source coupling — or fiat), and per-site
operator-norm sensitivities with the times they are achieved; plus the
registration window the process actually used. Globally: one uniform
threshold `delta` and (possibly) a supplied clock window `tau`. Each of
the six clauses — (CAP-real), (REG-dyn), (REG-thr), (REG-tau),
(REG-site), (RR) — is an independently coded predicate over such models;
(RR) is checked by a single pass over its own sentence, never by calling
the other predicates. The T1-d blocks-to-records clause is a seventh
predicate across e-folds tagged with disjoint source blocks.

Two kinds of models appear: an exhaustively enumerated family of 256
toggle models (every combination of: additivity on/off, sector
disjointness on/off, establishment on/off, source-support on/off,
threshold on/off, window-within-tau on/off, site-disjointness on/off,
support-nonemptiness on/off), and explicit-dynamics witnesses whose
sensitivities are *measured* operator norms on exactly constructed
finite-dimensional Hamiltonians (open chains of 2, 3, and 6 sites; the
retained (F4) hopping shape `q = 2`, `R = 1`).

## 3. The lattice, leg by leg

### 3.1 The equivalence (the consolidation theorem)

`(RR) <=> (CAP-real) AND (REG-dyn) AND (REG-thr @ own window)` — by
syntactic factorization: RR's sentence is the conjunction of (i) the
per-e-fold realization-with-disjointness sentence, which is (CAP-real) in

finite disjoint collection registered for the e-fold); (ii) the
establishment sentence, which is (REG-dyn); (iii) the threshold sentence
(records supported in the uniform-`delta`
sensitive set within the e-fold's window), which is (REG-thr) evaluated
at the e-fold's own window. The runner verifies the factorization
pointwise on all 256 toggle models with independent codepaths (T1), so
the formalization cannot silently drift. The corollary
`(RR) AND (REG-tau) => (REG-thr)` at the supplied window follows because
every window is then `<= tau` (T1). The **reverse direction is the
no-new-science-risk leg**: the conjunction implies RR, so declaring RR
declares nothing the five-clause inventory had not already declared.

An explicit 6-site open-chain instance (measured sensitivities `0.3133`
and `0.3085` at the two register sites, `delta = 1/10`, window
`0.6 <= tau = 1`)
satisfies all six predicates simultaneously (T2): the consolidated clause

### 3.2 (CAP-real) =/=> (RR): realization is not registration

The BR-license note's own `4^k` witness, formalized: assign `4^k` unit
records to e-fold `k` by fiat — no establishing process. (CAP-real) holds
exactly (additivity on every collection; prefix sums recomputed);
(REG-dyn) and RR are false (T3). The canonical cap
`K = (1 + 2*ceil(D*))^3 = 129^3 = 2146689` is recomputed from the cone
formula and the witness defeats it at `k = 11` — (CAP-real) alone never
carried the cap, which is exactly the split the BR-license note proved.
So RR is **strictly stronger** than (CAP-real): the consolidation
replaces the weaker clause by the conjunction it was always used inside,
never the other way.

### 3.3 (REG)-side =/=> (CAP-real): RR is a genuine join

The same real-dynamics records as T2 with the declared increment changed

RR fail (T4). Neither side of the conjunction is redundant; before this

### 3.4 (RR) =/=> (REG-tau): the clock window is irreducibly separate

A growing-window model (window `k` at e-fold `k`, `4^k` records each
established and `delta`-sensitive within its *own* window) satisfies RR
and fails (REG-tau) — and every fixed cap fails against it (T5). The
windows demanded by finite-speed registration of `4^k` records are
recomputed: `tau_11 >= 1.25 > 1`, `tau_30 >= 8036`, `tau_k -> oo`
(sympy). Consolidating (REG-tau) into RR would erase a load-bearing
clause; keeping it separate is forced by the lattice, and the clock/rate
`retained_no_go` is why the *type* of the clause differs: the window's
meaning needs the supplied clock map.

### 3.5 (RR) + (REG-tau) =/=> (REG-site): the optional sharpening

A 2-qubit witness with a real hopping bond (both sites measured
`delta`-sensitive at `t = 1`) carries four pairwise-orthogonal rank-1
joint projectors as records — orthogonality, completeness, and
both-site support all computed (T6). Four pairwise-disjoint nonempty
subsets of a 2-site set do not exist (all 81 assignments enumerated):
(REG-site) fails. Yet the joint-sector cap `d_site^N = 2^2 = 4` holds
with equality and a fifth orthogonal nonzero projection is impossible
(`sum P_i = I`). Since the `p = 0` selection needs only finiteness and
k-uniformity of `K` — both of which the joint reading `K = 2^{N_reach}`
retains — (REG-site) is **not load-bearing for the chain**: it demotes
from a required declared clause to an optional sharpening that shrinks
`K` from `2^{129^3}` to `129^3` and changes nothing in the pass set
(T6, T9). The reverse hole (REG-site) =/=> (RR) is witnessed too (T7).

### 3.6 (RR) =/=> (T1-d blocks->records): the parent Boundary is not absorbed

Hostile check of the consolidation's outer edge. The T1-d Boundary
contains a clause none of the five consolidated pins contains:
"independent disjoint source blocks register as disjoint records." On an
explicit 3-site chain, two disjoint source blocks `{0}` and `{2}` both
make the *middle* site `delta`-sensitive (measured `0.6708` each), and a
model whose two block-e-folds each register a record on site 1 satisfies
every RR facet while violating the blocks-to-records clause (T7).
(CAP-real)'s wording is per-e-fold realization and does not contain the
clause either (quoted verbatim in Section 1). Conclusion:
the consolidation's scope is exactly the five realization pins; **T1-d
stays the parent Boundary, untouched**, and anyone reading RR as
absorbing it is refuted by the witness.

### 3.7 The threshold facet: why `delta` lives inside RR and `tau` cannot

An e-fold-dependent threshold `delta_k = delta/2^k` shifts the
sensitivity radius by exactly `k ln 2` (sympy), so the reach `N_k` grows
without bound and k-uniformity of the cap is lost (T8). RR's wording
therefore must — and does — carry **one uniform supplied `delta`**. The
asymmetry with `tau` is typed, not aesthetic: `delta` enters the lattice
only as an operator-norm threshold (the cone formula's free symbols are
exactly `{tau, delta, J_V, v}`; every sensitivity in the runner is an
operator norm — no probability, no clock), while `tau`'s meaning requires
the supplied clock map per the clock/rate `retained_no_go`. So `delta`,
`J_V`, `s_X` are class parameters inside the declared RR (exactly as the
CAP-K note already treated them), and `tau` is a separate clause.
