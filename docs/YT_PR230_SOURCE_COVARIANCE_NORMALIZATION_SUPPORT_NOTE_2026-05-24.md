## Theorem

Let `Omega` be a finite signed-record block with a positive reference weight
`mu_0(epsilon)`. For a source profile `h`, define

```text
Z(h) = sum_epsilon mu_0(epsilon) exp(sum_x h_x epsilon_x),
mu_h(epsilon) = mu_0(epsilon) exp(sum_x h_x epsilon_x) / Z(h).
```

Then the source derivatives are exactly

```text
d log Z / d h_x = <epsilon_x>_h,
d^2 log Z / d h_x d h_y
  = <epsilon_x epsilon_y>_h - <epsilon_x>_h <epsilon_y>_h.
```

So the connected source-source row in the PR230 source coordinate is

```text
C_ss(x,y; h) = Cov_h(epsilon_x, epsilon_y).
```

In particular, under the uniform zero-source reference used in the minimal
PR230 packet, `<epsilon_x>_0 = 0`, so the origin score is the primitive signed
record itself and

```text
C_ss(x,y; 0) = <epsilon_x epsilon_y>_0.
```

## Normalization Consequence

The result fixes only the source leg. If the same source coordinate `h` is kept,
rescaling the source insertion

```text
epsilon_x -> lambda epsilon_x
```

changes the origin score to `lambda epsilon_x`; it no longer equals the
primitive signed record. Equivalently, one may absorb the change by a coordinate
redefinition `h -> lambda h`, but that is a different source-coordinate
convention, not a scalar/Higgs normalization theorem.

Thus the PR230 source packet has a canonical source-side connected row once
the signed-record source coordinate is adopted. The pole-row no-go still
applies to the Higgs/scalar leg:

```text
source-side C_ss fixed by RN source coordinate
scalar-side C_HH and C_sH still require canonical O_H / LSZ
```
