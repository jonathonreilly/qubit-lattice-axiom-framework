The decoder accepts only the exact identity/order chain, one common lawful

position equals the sum of the first fragments.  The three copies therefore
detect a single deleted/corrupted fragment; no error-correction theorem or
minimum redundancy claim is made.

For each trial, the counter schedule applies adjacent count-register
Fredkins from high index to low index, controlled by the copied first
fragment.  A one-hot token at count `k` moves to `k+1` exactly when that
physical fragment is one.  All other physical fields are retained, and
reversing the gates decrements in the correct reverse trial order.  The host
decoder reads the unary position and forms an exact rational `k/N`; it does
not supply the counted bits.

The identity/order/program fields are load-bearing qualification, not
decorative metadata.  Deleting a populated copy in any of them makes corpus
decoding undefined.  Deleting decoder fragment one yields a non-code triple;
deleting fragment zero additionally changes the physical counter and leaves
fragment/count mismatch.  Deleting an active Fredkin count resource also
leaves fragment/count mismatch.  Deleting one populated physical admission M2
from the first independent ratchet changes the exact frozen candidate word
from `101001` to `001001`; this is a changed physical prediction, not a silent
valid match to the held fixture.

1. Each completed Cycle-452 source block can swap its 83 visible bits into its
   own already inventoried sink.  The copied corpus and counter remain
   bit-for-bit readable because they occupy different physical M2, and inverse

   corpus erasure.
2. The Cycle-455 corpus reset swaps every 72 entry M2 and all seven unary
   counter M2 into a separate blank 79-M2 sink.  Visible fields become blank,

bit.  This is finite information/support accounting only.  It is not heat,

Discarding the sink is not part of the map.
