# Product-seed emitter milestone: integration plan

This is a drafting packet for one regular milestone after the structural-box
PR. No repository changes, physics replay, canonical cache, publication or
audit were performed here. The installed and weighted sources are separately
root-qualified for conditional provisional reuse. This packet does not compose
the emitter with a ladder coefficient box or a calibration theorem.

The [note draft](NOTE_DRAFT.md) has a complete current status block and the
three full source proof bodies. The [inventory](SOURCE_INVENTORY.md) names the
six scientific programs, launchers, exact inputs, actual outputs and review
limits. [SOURCE_INVENTORY.json](SOURCE_INVENTORY.json) pins all 152 copied files
(1,692,208 bytes), including qualification decisions and the existing parent.
The [body map](EMBEDDED_SOURCE_MAP.json) pins the byte ranges of the embedded
proofs. The three originals must remain byte-identical through integration.

## 2. Portable adaptation that still needs review

Keep all frozen programs and source evidence unchanged. Create separate helper
functions that return reports and take explicit input paths; let the primary
write its own canonical output. The complete adaptations require a focused
portability/delta review before execution. The reviewer should compare every
mathematical operation, branch, constant, assertion and input interpretation to
the pinned original, not merely compare output summaries.

Concrete changes needed:

1. The originals execute at module import, set process CPU limits, use their
   own `__file__` directory, and several parse command-line arguments or write
   there. Wrap their actual code in functions; remove import-time execution and
   output writes. Do not import a historical program unchanged into the primary.
   In particular the weighted author's 5-second hard CPU limit cannot remain
   an import-time limit on the combined 120-second process.
2. Apply one declared primary resource envelope. Runtime metadata for a
   canonical function call must describe that actual execution, while the
   historical caps and receipts remain separate. Preserve mpmath precision,
   exact Fraction/SymPy comparisons, source conventions, full dimensions and
   all pre-existing diagnostic cases. Do not relabel floating displays as
   outward enclosures or diagnose sampled points as uniform proof.
3. The local reviewer reads the author's `ALGEBRA_CERTIFICATE.json` to compare
   exact constants but independently derives its local matching/Gram checks.
   Preserve that limited dependency explicitly. The installed independent
   checker does not read author output for its conservative rational ceilings.
   The weighted checker reads the installed certificate and separately derives
   its integrals, full block factorization and weighted bounds. Keep these three
   independence scopes distinct in the combined report.
4. Preserve `run01_script.py`, `attempt_01/check_installed.py` and
   `runs/attempt_1/executed_source.py` as actual executed sources. A new helper's
   hash must never replace their recorded launch hashes. The route author had
   no standalone launcher source; its original command and execution receipt
   must not be retroactively described as a launcher program.
5. The weighted author and reviewer currently write different result formats.
   Return both full reports under clearly separate keys; assert the actual
   exact final bounds in the primary. Keep the initial $10^{72}$ result and
   weighted $10^{36}$ result separately visible, with the two corresponding
   finite horizons.

## 4. Positive-case mutation targets

Run bounded, isolated mutants of the adapted mathematical path against the
unmutated independently constructed witness/predicate. Preserve full sources,
outputs and exit codes for every attempted mutant, including any that survives.
At least one load-bearing positive-case mutation must be caught in each changed
check family. A hash mismatch alone is not the requested detection. Existing
wrong-formula discriminators provide exact target cases; do not silently count
their presence as execution of a mutation harness.

| Positive case to corrupt | Concrete mutation | Required mathematical failure |
|---|---|---|
| Full positive cell and physical scalar | Delete one vacancy term, or omit $2\kappa I$ in the full-qubit target | Nonzero exact addition-minus-target matrix; local reviewer already has a missing-vacancy discriminator |
| Phase direction | Replace the intended loop phase by its conjugate in one form factor while retaining the actual installed bonds | Intended right-emission/return notch fails; unitarity alone is insufficient |
| Noncommuting installed self-energy | Replace $XTY$ by $YTX$, or commute $T$ and $Q$ | Direct full-graph kernel/Schur residual is nonzero in the independent two-channel witness |
| Physical augmented matching sign | Flip the lower off-diagonal block | Direct tail elimination and proposed augmented matrix disagree exactly |
| Reference normalization | Delete the $dE=v_gdk$ Jacobian | Retarded resolvent jump no longer equals the two continuum weights |
| Common seed overlap and operator factors | Use diagonal overlap magnitudes only, discard off-diagonal Hermitian entries, or replace the square-sum by a maximum column error | Existing rectangular-isometry/aligned-column witness violates the claimed operator ceiling |
| All emitter directions | Keep only the resonant entry in the installed inverse, or delete the complementary inverse summand in the weighted factorization | Nonzero closed emitter response and full eight-dimensional inverse identity reject the mutation |
| Weighted cutoff and denominator products | Omit the taper derivative, use a wrong denominator-integral Jacobian, or drop a positive $U^3$ contribution | Exact cutoff/antiderivative identity or coefficientwise polynomial domination fails; a still-safe looser final decimal alone must not mask the algebra error |
| Complete localized correction | Remove emitter $y$ or $y'$ from the complete norm envelope while retaining the actual vector | The positive coefficientwise comparison against the full clock-plus-emitter expression fails |
| Finite horizon and graph distance | Replace $M-L-1$ by $M-L$ | The exact graph has a nonzero omitted-site amplitude at the true first hop, before the mutated threshold |

The canonical comparator also needs explicit scope checks for one $f$, one
$\rho$, fixed $\zeta=-e^{-4ik_0}\alpha$, the full scalar
$\nu+2\kappa$, literal $e^{-itK}$, the nonzero central residual ceiling,
all outputs and the finite horizon. Source-string or metadata checks of these
items are useful contract guards but are not substitutes for a mathematical
positive-case mutation. If additional old-aging/phase mutation witnesses are
added, use a nonzero two-energy column convention and an exact generator or
amplitude comparison. Label that new finite test and review it; the current
scripts do not already provide a general dynamical old-aging simulation.
