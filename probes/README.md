# Science probes — tasking location, work log and strategy

This directory is the repository's job list for executable science work that needs volume rather than judgment: re-execution,
mutation censuses, refuter re-runs, searches for counterexamples, parameter scans, and independent falsifier implementations.
The owner assigns workers (any model, any number); each worker runs tasks and pushes logs. Nothing here changes notes, runners
or packs, and nothing here is a claim. Logs are evidence addresses for later blocks.

## 0. Counts at creation (2026-09-18)
3178 runner re-executions, 20 mutation censuses (runners exposing `--list-mutations` on `main`), 6 searches, 6 scans, 2 judgment task types; `logs/probes/` is exempted from `.gitignore` on this branch only.

## 1. Location and branch
- Branch `ai/probes` (cut from `main`; never merged into `main`). Tasks: `probes/TASKS.json` (generated by `probes/generate_tasks.py`
  from every runner and refuter control in the checkout, plus the hand-written tasks in `probes/tasks/*.json`).
- Logs: `logs/probes/<task_id>/<worker>__<git-sha8>__<utc>.json` and `.txt` (full stdout), written by `probes/run_probe.py`.
- Summary: `python3 probes/harvest.py` (runs, hits, failures per task).

## 2. Worker protocol
1. `git fetch origin && git checkout ai/probes && git pull --rebase`.
2. Pick a task id from `probes/TASKS.json` (or `probes/TASKS.md`); run
   `python3 probes/run_probe.py <task_id> --worker <your-name> --model <model> [--seed N] [--minutes M] [--box AxBxL] [--extra "..."]`.
3. `git add logs/probes && git commit -m "probe: <task_id> <worker>" && git pull --rebase && git push origin ai/probes`.
   Commit only files under `logs/probes/`. Unique file names make conflicts impossible.
4. A HIT (the log's `hit: true`) is reported by opening an issue titled `probe HIT: <task_id>` with the log path. Do not "fix" anything.
5. Requirements: Python 3.12, numpy, scipy, sympy (the runners' own requirements). Searches are CPU-bound single processes; run several with different seeds in parallel.

## 3. Strategy — what each type buys
- **Type R (runner re-execution, tier 0, ~3300 tasks).** Every runner on the checkout re-run; a FAIL or a stdout hash differing from the pinned cache is a HIT. Buys: reproducibility across machines; drift detection. Assign the cheapest workers; one pass per week.
- **Type M (mutation census, tier 0).** Every declared mutation of every runner with a gate; a mutation that fails nothing or fails outside its family is a HIT. Buys: the runners' evidential value is only as good as their censuses.
- **Type F (refuter re-runs, tier 1).** Every refuting control in the science packs re-run (on `main` there are none under `.claude/science/**/specs/`; the campaign controls live on the open PR branches — fetch them with `git show origin/<branch>:<path>` into `probes/lib/` and add tasks, see section 6), with other seeds where the script allows (`--extra`). Buys: the refuting passes were run once by their authors.
- **Type S (searches, tier 1, admissibility lane).** Climbs for the open combinatorial cases of blocks 32–33. Any HIT changes a theorem's status (a counterexample to `c* = 1`, a tight sibling pair, a non-admissible restriction). No hit at scale is itself evidence recorded by the harvest. Buys the most per CPU-hour: assign broad seed/box sweeps.
- **Type X (scans, tier 1, admissibility lane).** Threshold locations and sphere-law measurements at sizes and couplings beyond the blocks. Buys: the map of memory (block 28) on more lines; the normalization `c(β)` and the `1/|m|²` law of blocks 34–35 as tables.
- **Type J (judgment, tier 2, any lane).** Independent falsifier implementations and re-implementations for any note with a Falsifiers section — the open PRs first (`#8023–#8033` compact/finite lanes, `#8077–#8083` native Ward lanes, `#8137–#8178` clock/charge/toe/admissibility lanes). Assign capable models; the return is a script plus numbers, logged, never a verdict.

## 4. Manual (type J) tasks
Create `probes/work/<stub>/<script>.py`, then log it: `python3 probes/run_probe.py J:falsifier-implementation --worker <name> --extra "python3 probes/work/<stub>/<script>.py"` — edit the task's command in a copy under `probes/tasks/` if the command needs more than `--extra`. Commit the script with the log.

## 5. Hit criteria and what happens next
Hits are collected by the harvest and read by the supervisor (or the owner); a confirmed hit becomes the input of a block (a refutation, a counterexample family, a corrected threshold). Logs without hits are cited by later notes as executed evidence with their log paths.

## 6. Extending the catalog
Add a task to `probes/tasks/<lane>.json` (id, type, lane, tier, command with `{SEED} {SECONDS} {A} {B} {L} {EXTRA}` placeholders, `hit_pattern`, `parse`, `what`), then `python3 probes/generate_tasks.py`. Lanes whose controls are on open PR branches: fetch the control with `git show origin/<branch>:<path>` into `probes/lib/` and reference it.
